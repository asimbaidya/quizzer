## 2. Strategy — the Testing Trophy

We follow the **Testing Trophy** model (integration-weighted), which is the modern
default for Vite + React apps. Bias effort toward tests that exercise real component
behaviour with mocked I/O, keep a thin E2E layer for critical journeys, and reserve
pure unit tests for logic that is genuinely algorithmic.

```
        /‾‾‾‾‾‾‾‾‾‾‾‾‾‾\      E2E (Playwright)        — few, critical journeys
       /                \
      /  ▇▇▇▇▇▇▇▇▇▇▇▇▇▇  \    Integration (Vitest+RTL) — MOST of our effort
     /____________________\
     \                    /   Unit (Vitest)            — pure logic only
      \__________________/
            Static         → TypeScript + Biome (already in place)
```

### 2.1 Tool selection & rationale

| Layer | Tool | Why this over alternatives |
| --- | --- | --- |
| Unit + Component + Integration | **Vitest** | Reuses the existing `vite.config.ts` (aliases, SWC, Tailwind plugin) with zero duplicate transform config. Jest would require a parallel Babel/SWC + moduleNameMapper setup and is slower here. Vitest is the industry default for Vite projects. |
| DOM assertions / rendering | **React Testing Library** + `@testing-library/jest-dom` | Tests behaviour through the accessibility tree, not implementation details — the standard for React. |
| User interaction | **`@testing-library/user-event`** | Simulates real user events (focus, typing, keyboard) more faithfully than `fireEvent`. |
| DOM environment | **jsdom** (via `environment: "jsdom"`) | Sufficient for component tests; lighter than a real browser. Use Playwright when real-browser behaviour matters. |
| Network mocking | **MSW (Mock Service Worker)** | Intercepts at the network layer, so the real generated `@hey-api` client + axios run unchanged. Far more robust than hand-mocking `src/client` modules. Same handlers reused in Node (Vitest) and browser (Playwright). |
| E2E | **Playwright** | Already installed; multi-browser, auto-wait, trace viewer, first-class CI story. |

**Explicitly not adding:** Jest, Cypress, Enzyme. They overlap with the above and
fragment the toolchain.

## 3. Tooling setup (do this first)

### 3.1 Dependencies to add

```bash
bun add -d vitest @vitest/coverage-v8 \
  @testing-library/react @testing-library/dom \
  @testing-library/jest-dom @testing-library/user-event \
  jsdom msw
```

### 3.2 Config files

- **`vitest.config.ts`** — merge with the existing Vite config so `@/*` aliases and
  plugins are shared. Key settings: `environment: "jsdom"`, `globals: true`,
  `setupFiles: ["./tests/setup.ts"]`, `css: true`, coverage provider `v8`,
  include `src/**/*.{test,spec}.{ts,tsx}` and `tests/unit/**`.
- **`tests/setup.ts`** — import `@testing-library/jest-dom/vitest`; start/stop the MSW
  server (`beforeAll/afterEach/afterAll`); polyfill `matchMedia` and
  `ResizeObserver` (Radix + `useMobile` need them); reset `localStorage` between tests.
- **`tests/mocks/`** — MSW `handlers.ts` (default happy-path handlers keyed off
  `openapi.json`), `server.ts` (Node), `browser.ts` (Playwright, optional).
- **`playwright.config.ts`** — `testDir: "./tests/e2e"`, `baseURL` from env,
  `webServer` running `bun run dev` (or `preview` against a built app),
  projects for chromium (+ webkit/firefox in CI), `trace: "on-first-retry"`.
- **`tests/utils/renderWithProviders.tsx`** — wraps components in
  `QueryClientProvider` (with a test `QueryClient`: retries off, no cache GC) and a
  TanStack Router test harness. All component tests render through this.

### 3.3 Directory layout

```
frontend/
  src/                         # unit tests colocated as *.test.ts(x) next to source
  tests/
    setup.ts
    mocks/{handlers,server,browser}.ts
    utils/renderWithProviders.tsx
    fixtures/                  # canned API payloads (quiz/test views, users)
    unit/                      # optional home for pure-logic tests if not colocated
    e2e/                       # Playwright specs (*.spec.ts)
  vitest.config.ts
  playwright.config.ts
```

Convention: **colocate** component/unit tests as `Foo.test.tsx` beside the source;
**E2E** lives in `tests/e2e`. Unit vs. component vs. integration is distinguished by
what a test imports and mocks, not by folder.

### 3.4 Scripts (`package.json`)

```jsonc
{
  "test": "vitest run",                    // unit + component + integration (CI default)
  "test:watch": "vitest",
  "test:ui": "vitest --ui",
  "test:cov": "vitest run --coverage",
  "test:e2e": "playwright test",
  "test:e2e:ui": "playwright test --ui"
}
```

> Note: this repurposes the current `test`/`test:ui` scripts (which point at
> Playwright) so `test` means the fast unit/component suite, matching convention.
> E2E moves under `test:e2e*`.

## 4. Core concepts → what to test

Priority: **P0** = ship-blocking, cover first · **P1** = important · **P2** = nice-to-have.
Layer: **U** unit · **C** component/integration (Vitest+RTL) · **E** end-to-end (Playwright).

### 4.1 Assessment answer logic — `src/lib/quiz.ts` · **P0 · U**
Pure functions; highest value-per-test in the codebase.
- `seedAnswers`:
  - seeds `[]` for `multiple_choice`, `null` for every other type when no prior response.
  - restores a prior `user_response` (string, `string[]`, boolean, and `false`).
  - `false` boolean must survive (guard against `??` swallowing falsy — verify).
- `toBatchAnswers`:
  - drops blank answers: `null`, `""`, whitespace-only string, empty array.
  - keeps `false` (a valid boolean answer) — regression-critical.
  - keeps non-empty strings/arrays; trims consideration for strings.
  - emits the nested `{ question_type, user_response: { question_type, user_response } }` shape correctly.

### 4.2 Countdown timer — `src/components/Student/Countdown.tsx` · **P0 · U + C**
- **U** `format`: `0` → `00:00`; sub-hour → `MM:SS`; ≥1h → `H:MM:SS`; zero-padding.
- **U** `remainingSeconds`: clamps at 0 for past deadlines; rounds correctly.
- **C** (fake timers): ticks down once per second; fires `onExpire` **exactly once**
  at zero; re-arms and re-fires when the `deadline` prop changes; switches to the
  `destructive`/`animate-pulse` variant at ≤60s; cleans up its interval on unmount.

### 4.3 Auth hook & guards — `src/hooks/useAuth.ts`, `_layout.tsx`, `login.tsx` · **P0 · U/C + E**
- **U** `isLoggedIn` reflects presence of `access_token` in `localStorage`.
- **C** `login()` stores the token then navigates to `/`; `logout()` removes the token
  and navigates to `/login`; `signUp` success navigates to `/login`; error paths call
  the error toast via `handleError` (mock the toast + navigate; MSW for the endpoints).
- **C** `beforeLoad` guards: `/_layout` redirects to `/login` when logged out;
  `/login` redirects to `/` when already logged in.
- **E** full login journey (see 4.11).

### 4.4 Login / signup / password forms — `routes/login,signup,recover-password,reset-password` · **P0 · C**
- Zod validation surfaces: invalid email, password `<8` chars, required fields — via
  `FormMessage`, on blur.
- Submit is blocked while `loginMutation.isPending`.
- Successful submit calls the mutation with typed form data.
- Server error (MSW 400/401) renders the toast and does **not** navigate.
- `signup` password-confirmation mismatch (verify the schema) surfaces an error.

### 4.5 QuestionCard rendering & interaction — `src/components/Student/QuestionCard.tsx` · **P0 · C**
One test group per question type:
- `single_choice`: renders a button per choice; selecting emits the choice text;
  selected choice gets the `default` variant.
- `multiple_choice`: toggling adds/removes from the array; checkbox reflects membership;
  emits the updated array (immutably).
- `true_false`: True/False buttons; emits boolean; selected state reflects `value`
  including `false`.
- `user_input`: typing emits the string.
- `disabled`: all inputs read-only (locked test / used-up attempts).
- Graded state: feedback panel shows only when `is_correct !== null`; green vs. red by
  correctness; appends `(score: N)` when score present.
- Image: renders `<img>` with `VITE_API_URL` prefix only when `image_url` is set.

### 4.6 Quiz-taking flow — `routes/_layout/quiz.$courseTitle.$quizId.tsx` · **P0 · C + E**
- **C** (MSW-backed): loading skeleton → questions render; "not found" when no data.
- Attempts math: `attemptsUsed` = max `attempt_count`; `attemptsLeft`;
  `canSubmit` false when attempts exhausted; unlimited-attempt badge/label.
- Submitted alert shows last score; copy differs when attempts remain vs. locked.
- Submit button toggles label `Submit`/`Resubmit`; disabled state hides the submit bar.
- On submit: calls `submitQuiz` with `toBatchAnswers` payload; success toast +
  query invalidation (re-seed answers on refetch); error toast on failure.
- Empty quiz → "no questions yet" message.

### 4.7 Test-taking state machine — `routes/_layout/test.$courseTitle.$testId.tsx` · **P0 · C**
Cover **every** `TestStatus` branch — this is the most stateful screen:
- `not_opened` → "Not open yet" + `window_start`.
- `not_participated` → "Test missed" destructive alert.
- `not_started` → intro + Start button; Start calls `startTest`, success toast, invalidate.
- `in_progress` → questions editable, Countdown rendered, submit bar visible.
- `in_waiting_for_result` → locked, "awaiting results" alert, no submit bar.
- `completed` → score alert, locked.
- **Deadline logic**: `deadline = min(start_time + duration, window_end)` — unit-test the
  `useMemo` calculation directly if extracted, else assert Countdown gets the right prop.
- **Auto-submit on expiry**: with fake timers, expiring the Countdown triggers exactly
  one `submitTest`, shows the "Time is up" toast, and never double-submits
  (`autoSubmittedRef` guard) even if the timer fires again.

### 4.8 Teacher authoring — `components/Teacher/*`, `routes/_layout/teach.*` · **P1 · C + E**
- Create Course / Quiz / Test / Question dialogs: form validation, submit calls correct
  service with correct payload (MSW), success closes dialog + invalidates list, error toast.
- Assessment kind routing (`teach.$courseTitle.$kind.$assessmentId`) resolves quiz vs. test.
- **E** happy path: teacher creates a course → adds a quiz → adds a question.

### 4.9 Admin user management — `components/Admin/*`, `components/Pending/*` · **P1 · C**
- `DataTable` (TanStack Table): renders rows from data, pagination controls, empty state.
- AddUser / EditUser / DeleteUser: form + confirmation dialogs; correct service calls;
  optimistic/invalidation behaviour; error handling.
- PruneImages confirmation + action.
- Pending users approval flow.

### 4.10 Notes editor — `components/Student/note/*` · **P1 · C**
- `NoteEditor` / `NoteSection`: create, edit, delete sections; content persists to the
  API (MSW); `AutoTextarea` grows with content; `flag-schemes` rendering.
- Route `notes.$noteId` loads and renders an existing note; `notes.index` lists notes.

### 4.11 Cross-cutting / shared · **P1–P2 · C**
- `src/utils.ts` `extractErrorMessage` / `handleError`: AxiosError message, FastAPI
  validation array (`detail[0].msg`), string detail, fallback "Something went wrong."
  (**P0 · U** — pure and widely used).
- `getInitials`: 1 word, 2 words, 3+ words (first two), casing.
- `src/lib/utils.ts` `cn`: merges + de-dupes conflicting Tailwind classes.
- Hooks: `useCopyToClipboard`, `useMobile` (matchMedia), `useCustomToast`.
- Common components: `ErrorComponent` / error boundary, `NotFound`, `Appearance`
  (theme switch via next-themes), `Pagination`.

### 4.12 E2E critical journeys — Playwright · **P0/P1 · E**
> **Setup + how-to lives in `tests/e2e/README.md`.** E2E runs against the real
> running stack (`./scripts/dev.sh up && ./scripts/dev.sh seed`), using the
> `.test-credentials.md` accounts via the `fixtures.ts` `loginAs` fixture.
> Done so far: smoke (2), auth journey (3), student quiz navigation (1).

Keep this set small and stable; back it with a seeded backend + the
`.test-credentials.md` accounts.
1. **Auth**: visit protected route → redirected to login → log in → land on home;
   reload keeps session; logout returns to login. (P0)
2. **Student takes a quiz**: open quiz → answer each question type → submit →
   see score → resubmit within attempts. (P0)
3. **Student takes a timed test**: start → answer → submit before deadline;
   separately, let the timer expire → auto-submit. (P0, use a short-duration seeded test)
4. **Teacher authoring**: create course → quiz → question, verify it appears to a
   student. (P1)
5. **Admin**: create a user, edit role, delete. (P1)

## 5. Conventions & best practices

- **Query the accessibility tree** (`getByRole`, `getByLabelText`) over `getByTestId`;
  reserve `data-testid` for E2E anchors and untitled elements. (Login already has some.)
- **Mock at the network boundary (MSW)**, never mock the generated `src/client` SDK.
  Keep default happy-path handlers global; override per-test with `server.use(...)`.
- **A fresh `QueryClient` per test** with `retry: false` and no caching to avoid leakage.
- **Fake timers** (`vi.useFakeTimers()`) for Countdown / auto-submit; always restore.
- **Reset state between tests**: `localStorage.clear()`, `server.resetHandlers()`,
  `vi.clearAllMocks()` in `afterEach`.
- **Test behaviour, not implementation**: assert on rendered output and emitted calls,
  not internal state or class names (except where variant styling is the contract).
- **Fixtures** in `tests/fixtures` typed against `src/lib/quiz.ts` and the generated
  client types so payload drift is caught by `tsc`.
- **Deterministic dates**: inject/freeze `Date` for window/deadline logic.
- Keep E2E independent of unit/component runs; they must be runnable separately in CI.

## 8b. Harness gotchas (read before touching config)

These were resolved during initial setup; a fresh agent must not "simplify" them
away without re-hitting the failure.

- **We run under Bun** (`bunx vitest`). Bun lacks Node's V8 inspector coverage API,
  so `@vitest/coverage-v8` fails with *"Coverage APIs are not supported"*. We use
  **`provider: "istanbul"`** (`@vitest/coverage-istanbul`) instead. Do not switch back.
- **zod under rolldown-vite (Vite 8):** the bare `zod` specifier resolves via zod's
  `@zod/source` export condition to raw `src/index.ts`, whose namespace lacks the `z`
  object → `TypeError: z.object is undefined` in any file importing zod (e.g.
  `login.tsx`). Fix: `vitest.config.ts` aliases `zod` → **`tests/shims/zod.ts`**, which
  re-exports the built entry and re-attaches `z`. Also `optimizeDeps.exclude: ["zod"]`.
  If you bump zod/vite, re-run `src/routes/login.tsx` tests to confirm the shim still holds.
- **Routing tests use the real route tree** (`tests/utils/renderRoute.tsx` +
  `createMemoryHistory`), not a hand-rolled router. This exercises `beforeLoad` auth
  guards and params exactly as production. Seed auth via the `token` option; MSW must
  answer `/users/me` (the sidebar calls it) or unhandled-request errors will fail tests.
- **jsdom polyfills** live in `tests/setup.ts`: `matchMedia`, `ResizeObserver`,
  `scrollTo` (jsdom's throws — assigned unconditionally), and Radix pointer-capture stubs.
- **Countdown helpers** (`format`, `remainingSeconds`) are exported from the component
  purely for unit testing — keep them exported.
